# Постановка задачи на User Story: дистанционное закрытие ИИС

Постановка составлена по шаблону из пяти компонентов: роль, цель, формат результата, тон и стиль, контекст. По ней исполнитель может подготовить User Story с критериями приёмки, не задавая уточняющих вопросов.

## Постановка

| Компонент | Содержание |
|---|---|
| Роль | Бизнес-аналитик финтех-компании, специализация — налоговые процессы и цифровое взаимодействие с ФНС |
| Цель | User Story для функции отправки комплекта документов (копия паспорта, договор, справка ФНС) при закрытии индивидуального инвестиционного счёта (ИИС) без посещения офиса |
| Формат результата | User Story в формате «Как <роль>, я хочу <действие>, чтобы <ценность>» и не менее 7 критериев приёмки |
| Тон и стиль | Деловой, на русском языке, с терминологией финтеха и налогообложения. Аудитория — backend- и frontend-разработчики и Product Owner |
| Контекст | Процесс закрытия ИИС и улучшение, которое нужно заложить (ниже) |

## Контекст процесса

1. Клиент инициирует закрытие ИИС в мобильном приложении.
2. Заполняет заявку с персональными данными.
3. Загружает комплект документов: копию паспорта, договор, справку ФНС.
4. Система отправляет документы в ФНС.
5. Отдел проверки документов проверяет справку ФНС в течение 5 рабочих дней.
6. Если в справке найдена ошибка, клиент повторно загружает исправленный документ **без повторного заполнения всей заявки**. Это улучшение по сравнению с текущим процессом, где заявку приходится отменять и начинать заново.

## Что должны покрыть критерии приёмки

- допустимые форматы файлов;
- максимальный размер файла;
- обработку ошибок при отправке документов;
- повторную загрузку одного документа без потери остальных данных заявки.
